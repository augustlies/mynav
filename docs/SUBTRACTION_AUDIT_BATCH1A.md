# MyNav 减法审计 · Batch 1A 执行记录

> 角色：产品主编 / UX 审计。范围：36 个书签的入口层级与首屏信息架构。
> 本次只收敛入口与视觉噪音，不改数据层、卡片渲染和既有功能。

## 一、首屏信息架构问题（按严重程度）

### P0 · 首屏同时出现两套“导航 + 工具”

证据：

- 改版前 `index.html` 顶栏有 12 个功能按钮：白噪音、秘卷、暗月、结界、整理、主题、指南、随机、晨报、飞鸽、寻星镜、云同步；加上品牌入口共 13 个按钮。
- 同一屏的索书条还承载视图切换、3 个快捷筛选、4 个时间窗和馆藏统计；首张卡片要到 `y≈333` 才出现。
- 顶栏工具和索书条筛选互不从属，用户无法判断“先找书”还是“先配置系统”。

涉及文件：`index.html`、`styles.css`。

### P0 · 一个功能有多个同级入口

证据：

- 待编目匣：左栏书脊入口 + 移动端快捷入口。
- 黄铜工具尺：左栏书脊入口 + 移动端快捷入口。
- 晨报、飞鸽、寻星镜：顶栏入口 + 移动端快捷入口。
- 视图切换：索书条内入口，同时还有 `G` 键和命令路径。

结果不是“可发现性更强”，而是重复占位：36 条内容却先教用户认识 20 多个工具。

涉及文件：`index.html`、`js/uncatalogued.js`、`js/brass-tools.js`、`js/ephemeris.js`、`js/courier.js`、`js/federation.js`、`js/star-map.js`。

### P1 · 搜索框周围的信息抢走检索主任务

证据：

- 改版前索书条右侧同时放着视图切换、私人典藏、常驻案头、星轨编年、四个时间窗和馆藏统计。
- 搜索输入区是首屏唯一的“立即行动”，但视觉上被这些辅助控件切成多个焦点。
- 这些控件并非高频检索动作，且其中多数已有键盘或命令路径。

涉及文件：`index.html`、`styles.css`、`app.js`、`js/almanac.js`、`js/star-map.js`。

### P1 · 辅助面板在首屏制造“系统正在运行”的错觉

证据：

- 改版前遥测机关台、星群连珠与月相时间窗出现在卡片上方。
- 遥测台默认折叠，却仍保留整条机关台外框；星群连珠是工作流入口，不是浏览 36 条书签的必经步骤。
- 首屏因此像“控制台首页”，而不是“私人图书馆目录”。

涉及文件：`index.html`、`styles.css`、`js/telemetry.js`、`js/constellations.js`、`js/almanac.js`。

### P2 · 卡片自身动作偏多，但不属于 Batch 1A

证据：

- 36 张卡片每张都有收藏、藏书票、批注触发、索书号等动作；藏书票和批注是核心产品辨识度，不能按“降噪”粗暴删除。
- 真正的问题是它们与首屏外围工具同时争夺注意力，而不是卡片内部功能本身有错。

涉及文件：`app.js`、`js/marginalia.js`、`js/amber.js`、`styles.css`。

结论：Batch 1A 不动卡片抽离/置顶、卡片背面、藏书票和批注逻辑；只把卡片外围的系统工具移出第一屏。

## 二、保留 / 降级 / 下线清单

### 保留

- 品牌：`EX LIBRIS`、馆名、主题切换（`#btn-theme-toggle`）。
- 检索：搜索输入、引擎切换、命令入口、守馆人 AI 的输入态路由。
- 分类：左栏/移动端分类书脊 `#spine-nav`。
- 卡片：36 张卡片、收藏、藏书票、批注、琥珀死链兜底。
- 键盘路径：`/`、`R`、`U`、`S`、`T`、`G`、`M`、`?`、`j/k`、`v` 等既有快捷键与命令。

### 降级到二级入口

- 视图切换：书本目录 / 穹顶星图。
- 白噪音、活字秘卷、待编目匣、暗月、考场结界、整理、快捷键指南、随机开卷。
- 观星晨报、飞鸽传书、联邦寻星镜、云同步。
- 私人典藏、常驻案头、星轨编年与时间窗。
- 星群连珠、遥测机关台。
- 移动端对应快捷入口。

落点：卡片之后的 `BACK MATTER · 馆务索引`（`.footer-utility-rack`）。理由：低频但仍有价值的馆务应可发现、可键盘直达，不必占据首屏；同时不删除任何 DOM ID 或模块能力。

### 下线

- Batch 1A 不永久删除任何功能。
- 建议下一批评估“视觉下线”而非能力下线：重复的移动端同义入口、默认展开的机关台外框、首屏统计文案。
- 若后续确认某入口 30 天内无使用，再按“先隐藏入口、保留命令与模块、最后评估删除”的顺序处理。

## 三、第一屏重设计

第一屏只保留四层，顺序固定：

1. **品牌**：`EX LIBRIS / 个人数字收藏馆` + 主题切换。
2. **搜索**：一条索书框，引擎、输入、清除与命令入口都在框内。
3. **分类**：桌面左栏纵向书脊；移动端横向可滚动分类条。
4. **卡片**：分类标题后直接进入馆藏卡片。

收纳规则：

- 任何“配置系统”“切换模式”“打开工具”“查看统计”的控件都不进第一屏。
- 统一收进页尾馆务索引，按“视图 / 工具 / 筛选 / 星图 / 遥测”分组。
- 高频动作优先保留键盘路径，避免二级入口变成唯一通道。

验收基线：1440px 下首张卡片 `y≈253`；顶栏功能按钮仅 `#btn-theme-toggle`；索书条外侧功能控件为 0。

## 四、给 Codex 的分批任务清单

### 第一批 · Batch 1A（本次执行）

目标：入口收敛与视觉降噪，不改数据层。

- 顶栏只保留品牌与 `#btn-theme-toggle`。
- 索书条只保留搜索；视图、筛选、统计与工具移出。
- 卡片之后新增 `.footer-utility-rack`，承接所有低频入口与辅助面板。
- 遥测机关台默认折叠并弱化外框。
- 不改 `data.js`、`localStorage` Schema、DOM ID、`window.NavApp.*` 钩子、卡片抽离/置顶、藏书票、批注。
- 通过 `validate.js`、`phase05-perf/acceptance.js`、`icons-2026-10-21/acceptance.js`，以及 9 档宽度零横向溢出。

### 第二批 · 二级入口再分组（建议）

- 把页尾馆务索引拆成可折叠的“馆务 / 星图 / 同步”三组，默认只显示组标题与一行摘要。
- 合并桌面与移动端重复的同义入口，但保留所有 ID 与命令路径。
- 评估是否把“随机开卷”“快捷键指南”改为纯命令 + 页尾文字链接。
- 不改卡片与数据层。

### 第三批 · 卡片外围降噪（建议）

- 只处理卡片外框、索书号、藏书票触发器的视觉权重。
- 不改卡片抽离/置顶渲染、背面、藏书票内容、批注数据。
- 以真实浏览器对比 36 张卡片的可读性与键盘焦点顺序。

### 第四批 · 文案与可发现性（建议）

- 把页尾“馆务索引”文案压缩成一句操作说明。
- 给二级入口补充一致的 `aria-label` 与命令提示。
- 用键盘路径与页尾入口做双通道验收。
